🔍 Architecture

SIEM: Security Information and Event Management

🔧 Core SIEM Components

  • Log Ingestion: Centralized collection of logs using agents or agentless protocols (e.g., syslog, WMI, REST APIs) from diverse sources like firewalls, IDS/IPS, operating systems, and cloud services.
  • Parsing & Normalization: Converts raw log data into structured formats using custom parsers, regex, or vendor-defined schemas, enabling consistent search and analysis.
  • Correlation Engine: Rule- and behavior-based correlation of normalized events to identify suspicious patterns, lateral movement, or multi-stage attacks.
  • Use Case Framework: Modular library of security use cases (e.g., brute force detection, privilege escalation) aligned with frameworks like MITRE ATT&CK.
  • Alerting & Dashboards: Real-time alerts delivered via email, SMS, ticketing systems; customizable dashboards using widgets, threat maps, and KPIs.
  • Retention & Forensics: Long-term log storage for compliance (e.g., GDPR, HIPAA) and forensic analysis. Supports cold/hot storage and legal hold tagging.

🛠️ Technical Stack

  • Apache Kafka: Distributed event streaming platform used to buffer high-throughput log data before processing, ensuring decoupling of producers/consumers.
  • Logstash/Fluentd: Open-source data processing pipelines for log ingestion, transformation, and routing into storage/indexing systems.
  • Apache Solr / Elasticsearch: Search engines used to index logs for real-time querying with full-text search, aggregations, and custom queries.
  • Hadoop HDFS: Distributed file system to store petabytes of historical logs for compliance and forensic retrieval, supports batch processing with MapReduce or Spark.
  • Apache Spark: In-memory distributed computation engine used for real-time analytics, machine learning, and log enrichment.
  • Security Data Lake: Centralized log repository aggregating structured and unstructured data from security telemetry for advanced analytics and AI/ML applications.
